# v0.4.0 Engineering Prompt

Integrate the newly imported Vector EVCC BSW stack into the existing EVCC_demo
Windows PC simulation with the smallest practical compatibility surface.

Requirements:

- Preserve protocol-stack algorithms and generated behavior.
- Discover C/C++ sources and header directories recursively from the existing
  L0 BSW, L1 RTE, L2 APP, and top-level source roots.
- Keep `_Appl_Rand.c` and `_Appl_Time.c` out of the PC build when their services
  are supplied by the host integration adapter.
- Create missing AUTOSAR/RTE/basic-service compatibility headers under
  `L0_BSW_Layer/_Common/Autosar_Common`.
- Replace `StartApplicationCcs.h` includes with `_ApplScc_CbkStubs.h` where
  explicitly required and correct include names to match real files.
- Define `NvM_RequestResultType` as `uint8` in `NvM.h`.
- Define `PduLengthType` as `uint16` through `Std_Types.h`.
- Define `EcuM_WakeupSourceType` as `uint8` in `EthIf_GenTypes.h`.
- Adapt callback signature mismatches in the host integration layer.
- Disable AUTOSAR MemMap section/MPU processing for PC builds through
  `MICROSAR_DISABLE_MEMMAP`, while retaining an opt-out for target builds.
- Update VSCode IntelliSense paths and defines.

Verification:

- Clean parallel full-project rebuild.
- Existing layer-decoupling, OS tick, OS API, and OS boundary checks.
- Runtime smoke check, with Windows policy failures recorded as environment
  restrictions rather than build failures.
- Secret, generated-artifact, and large-file checks before Git upload.

Archive the design, prompt, implementation summary, tests, version record, and
changelog under `main/products/evcc-pc-freertos-sim`.
