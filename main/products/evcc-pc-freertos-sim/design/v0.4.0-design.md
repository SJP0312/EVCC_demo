# v0.4.0 Design

## Goal

Integrate the imported Vector EVCC BSW protocol stack into the existing Windows
PC simulation so the complete project compiles with MinGW while preserving the
protocol algorithms and the existing layered OS simulation.

## Target Users

- EVCC developers validating protocol-stack integration on a Windows PC.
- Embedded engineers preparing the same source tree for a later ECU toolchain.

## Main Scenarios

- Build all existing application, RTE, OS, generated configuration, and EVCC BSW
  sources with one Makefile command.
- Resolve missing AUTOSAR, RTE, SchM, and basic-service dependencies through a
  clearly isolated PC compatibility layer.
- Ignore target linker sections and MPU placement during host simulation.
- Keep generated and protocol implementation behavior unchanged except for
  explicitly requested include-name compatibility corrections.

## Engineering Modules

- Recursive Makefile source and include discovery.
- `L0_BSW_Layer/_Common/Autosar_Common` PC compatibility headers and callbacks.
- AUTOSAR base-type compatibility in `Std_Types.h`, `NvM.h`, and generated
  Ethernet interface types.
- Host MemMap no-op path controlled by `MICROSAR_DISABLE_MEMMAP`.
- VSCode IntelliSense include paths and preprocessor configuration.
- Engineering archive and build/test evidence.

## Acceptance Criteria

- `mingw32-make -j4 rebuild` compiles and links `build/EVCC_demo.exe`.
- No missing-header, undefined-reference, or MemMap section errors remain.
- Existing OS API, boundary, tick, and layer-decoupling checks pass.
- Build artifacts and local executable files remain excluded from Git.
- Protocol-stack algorithm implementations are not changed.
- Any host execution restriction outside the build is identified separately.

## Test Standards

- Run a clean parallel full-project rebuild.
- Run all non-smoke PowerShell verification scripts.
- Run the smoke test and record environmental execution-policy failures
  separately from compiler/linker failures.
- Scan new files for private-key containers, common secret patterns, and files
  larger than the normal Git hosting limit.

## Out Of Scope

- ECU linker scripts, MPU configuration, and target MemMap placement.
- Functional vehicle/charger communication validation.
- Production key or certificate provisioning.
- Bypassing or weakening Windows enterprise application-control policy.
